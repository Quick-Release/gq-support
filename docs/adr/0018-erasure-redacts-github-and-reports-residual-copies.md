# Erasure redacts GitHub issues and reports residual copies

GETQUICK acts as the Client's processor, so a Reporter erasure starts from the Client's WordPress privacy tools or from an Operator acting on the Client's instruction. GitHub issues carry only pseudonymous attribution: the environment, an installation reference and a short hash of the Reporter subject, never a name or email. On erasure the service purges its own records and edits the App-authored issue body to replace the Reporter's text with an erasure notice. It keeps the issue and its marker, because the GitHub App cannot delete issues and the issue is also the Client's project record. GitHub edit history, notification emails and Developer comments are residual copies that the service cannot reach. Erasure reports them as partial and hands them to an Operator for review; it never claims completion.

## Considered options

- Leave GitHub untouched and erase only the service records. Rejected, because Reporters can type personal data into their text.
- Delete the issue. Rejected, because it needs a broader App permission and would destroy the Client's engineering record.
