# Installation-scoped attestation is not cross-site identity

WordPress attests its current Reporter to the Worker using a revocable, per-installation signed request; the Worker resolves the approved Client and project repository from that credential and enforces ownership by installation and immutable Reporter subject. We deliberately do not use a site login or matching email as a cross-installation identity: a compromised site can impersonate local users, so allowing its attestation to activate cross-site manager grants would breach other installations. Cross-installation management remains deferred until it has independent person authentication and explicit service-side grants. This trades immediate multi-site convenience for a bounded site-compromise blast radius; see [support security design](../support-security-design.md).
